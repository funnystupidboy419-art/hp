# 生成物の形式判定

作業に入る前に、まず**判定と理由だけ**を出す。判定を出してから作る。

## 手順

1. 何を作りたいかが分からなければ、一言で聞く（推測で作り始めない）。
2. 下の基準で **チャット / Artifact・ドキュメント / コード** のどれかに判定する。
3. 回答は次の形で短く出す:
   - **判定**: どれか1つ
   - **理由**: 基準のどれに当たるかを1〜3行
   - **作るもの**: 具体的に何をどこに作るか（コードならファイルの場所も）
4. ユーザーが別の形式を望んだら、それに従う。

## 判定基準

### チャット向き
- 1回読めば終わるもの（相談、壁打ち、文章の下書き、アイデア出し）
- 形が決まっていない段階のもの（まず方向性を決めたい場合）
- 学級通信の文面、授業の発問案、メール文など、コピーして使う短い文章

### Artifact／ドキュメント向き
- 1枚もののページや資料で、リポジトリに入れるほどではないが URL で共有したいもの
- 例: ワークシート、グラレコ、研修資料、配布用のまとめ

### コード（このリポジトリ）向き
- サイトに載せて、継続的に見たり更新したりするもの
- 毎日・毎週など、同じ手順を繰り返すもの（自動化する価値があるもの）
- データが増えていくもの（記事、記録、一覧）
- 他の先生と URL で共有し続けるもの

## 迷ったとき
- 「一度きり」か「繰り返す・増える」かで分ける。一度きりならチャットか Artifact、繰り返すならコード。
- 共有の要否で分ける。共有しないならチャット、共有するなら Artifact かコード。
- それでも決まらないときは軽い方（チャット）から始め、必要になったら格上げを提案する。

## 注意
- 児童生徒・保護者・個々の教職員など、個人が特定される情報は入力も出力もしない。
- コードに判定した場合は、このリポジトリの `CLAUDE.md` のルール（記事は `data/news.json` を `scripts/update_news.py` 経由で更新、push 前に `validate_site.py` など）に従う。
