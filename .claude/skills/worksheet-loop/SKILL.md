# ワークシート検証ルーティン

**作る → 生徒役が解く → 深まりを判定 → 先生が解説をチェック → ダメ出しを取り込んで作り直す**
これを1周ずつ回す。周回数は毎回必ず報告する。

## 原則（全ラウンド共通）

1. **難易度と深さを分ける。** 「難しくする」は改善ではない。
2. **件数を埋めない。** 問いが弱いなら削る。問題数より1問の質。
3. 生徒役の答案を「正解した／しなかった」で読まない。**何が見えたか**で読む。
4. 児童生徒・保護者・個々の教職員など、個人が特定される情報は入力も出力もしない。
   生徒役は架空の学力層で、名前も学校名も持たない。
5. 先生のダメ出しは必ず `worksheets/_review-notes.md` に追記する。同じ指摘を二度させない。
6. **先生に「ダメ出しください」と聞かない。** 整った生成物には「ダメだ」が出にくい。
   `references/review-questions.md` の「差異探し」の5つの問いの形で出す。
7. **放っておくと無難なものができる。** ねらいと直結しない、どの単元にも置ける問いが
   混ざる。critic の D0（ねらいとの直結）で必ず外す。

## 2つのモード

| | A4 1枚モード | **A3横5ブロックモード** |
|---|---|---|
| 使うとき | 1時間ぶんを素早く試したい。検証が主目的 | 本番。単元分をまとめて作り、印刷して配る |
| 形式 | Artifact（A4縦1枚） | `a3-tangen-worksheet` スキルに従う（A3横・5ブロック・生徒用＋赤刷り） |
| 出力 | HTML | Word/PDF（コードから二重ビルド） |

**本番は A3 モード。** A3 モードでは、紙面・赤刷り・根拠カード・単元テストとの対応は
`a3-tangen-worksheet` スキルが決める。このスキルはそこに**検証の工程を足すだけ**で、
レイアウトや twips の値、ビルド手順を上書きしない。

A3 モードでは Round 1 の前に `a3-tangen-worksheet` を読む。衝突したら a3 側を優先する。

### A3 モードでの各ラウンドの違い

- **Round 1** — a3 スキンの手順で作る。テキスト版（`vN-sheet.md`）は**5ブロックの見出しで**書く。
  生徒役に渡すのはテキスト版。Word/PDF を直接読ませない。
- **Round 2** — 生徒役は50分の流れとして解く（①5分 ②5分 ③20分 ④12分 ⑤8分）。
  **④JUMP課題で3体の反応が割れるかが最大の検証点。**
- **Round 3** — critic は9観点に加えて J1〜J4（JUMPの成立／練習とのつながり／根拠カード／時間配分）を見る。
- **Round 3.5** — auditor は11〜16（生徒用⇄赤刷りの対応／カード番号／分類の図に答え／補助線の成立／
  ページ数＝時数／角度ラベルの検算）も見る。PDF があれば `pdfinfo` の数値を報告に入れる。
- **Round 5** — 先生に出すのは生徒用と赤刷りの両方。削り順はブロック単位で書く。

## Round 0 — 準備

```bash
cat worksheets/_review-notes.md          # 先生の採用基準。必ず先に読む
ls worksheets/                           # 過去の単元と版
```

確定させること（分からなければ**作る前に一言で聞く**）:
- 単元（教科書・章・単元名）
- 何時間分か（1時間なら問題は絞る）
- この時間のねらい（生徒が何をできるようになるか、1文）

A3 モードではさらに（`a3-tangen-worksheet` の「最初に確認すること」と同じ）:
- 教科書のページ範囲と**時数**（＝作る枚数）
- 単元を貫く課題
- **根拠カードを何枚に絞るか**（10枚前後）と、前の単元から続く番号の開始値
- 単元テストの有無。市販プリントならその大問構成

## Round 1 — 作成

`artifact-design` スキルを読んでから、Artifact として公開する。

**同時に、問題文だけのテキスト版を保存する**（エージェントに読ませるため）:

```
worksheets/<単元スラッグ>/v<N>-sheet.md
```

テキスト版には問題文・図の説明・解答欄の形式を書く。図は文章で説明する
（「AB＝AC の二等辺三角形 ABC、底辺 BC 上に点 D, E」のように）。

## Round 2 — 生徒役が解く

`student-math-jhs` エージェントを **3体同時に** 起動する（A / B / C）。
各エージェントに渡すもの:
- `v<N>-sheet.md` のパス
- どの生徒か（生徒A／生徒B／生徒C）
- 「解答例は見ないこと」の明示

出力を保存する:
```
worksheets/<単元スラッグ>/v<N>-student-A.md
worksheets/<単元スラッグ>/v<N>-student-B.md
worksheets/<単元スラッグ>/v<N>-student-C.md
```

## Round 3 — 深まりの判定

`worksheet-critic` エージェントを起動する。渡すもの:
- `v<N>-sheet.md`
- 生徒役3体の答案すべて
- `.claude/skills/worksheet-loop/references/deepening-moves.md`
- `worksheets/_review-notes.md`

出力を `worksheets/<単元スラッグ>/v<N>-critique.md` に保存する。

## Round 3.5 — 横断監査

`worksheet-auditor` エージェントを起動する。渡すもの:
- 本紙（Artifact の HTML ファイルのパス）
- `v<N>-sheet.md`

内容の質は見ない。**書類のあいだの食い違いだけ**を拾う役。
改訂版では「前の版から削った問題への参照が解答編に残っている」が最も出やすい。

出力を `worksheets/<単元スラッグ>/v<N>-audit.md` に保存する。
**重大な指摘が1件でもあれば、先生に出す前に直す。**

## Round 4 — 自動で作り直すかの判断

critic の問別平均を見る。

| 状態 | 対応 |
|---|---|
| 平均 2.5 未満の問題がある | Round 1 に戻って差し替え（**先生に出す前に直す**） |
| 全問 2.5 以上 | Round 5 へ |
| 生徒Cが「作業だった」と言った問題がある | 平均に関係なく差し替えを検討 |
| 生徒Aが全滅した問題がある | 深さではなく足場の不足。足場を足して残す |

自動で回すのは**最大2周**。それで基準に届かないときは、届かないまま
Round 5 に出して「ここが詰まっている」と先生に相談する。隠さない。

## Round 5 — 先生ゲート（人の判断）

先生に出すのは次の4つだけ。長い報告は出さない。

1. 改訂後ワークシートの Artifact URL
2. **A4 1枚ぶんのサマリ**
   - 何を変えたか（問ごとに1行）
   - なぜ変えたか（生徒役の反応を根拠に、1行）
   - 自動ラウンドを何周したか／監査の検出件数
3. 先生の判断が必要な点（1〜3点。なければ「なし」）
4. **差異探しの5つの問い** — `references/review-questions.md` をそのまま出す

「ダメ出しをください」と書かない。「自分ならここを違うふうにやる、はどこですか」と聞く。

ここで止まる。先生が解説をチェックするまで次に進まない。

## Round 6 — ダメ出しの取り込み

先生の指摘を2つに分けて扱う。

- **この単元限りの修正** → そのまま直して Round 1 へ
- **今後も効く採用基準** → `worksheets/_review-notes.md` に追記してから Round 1 へ

追記の形:
```markdown
## YYYY-MM-DD（<単元>）
- 指摘: <先生の言葉をそのまま>
- 基準: <次回から守ること。判定できる形で書く>
```

「基準」は判定できる文にする。
悪い例: 「もっと考えさせる問題にする」
良い例: 「穴うめは1ワークシートに1問まで。残りは記述か反例づくりにする」

**先生の言葉は言い換えずにそのまま写す。** 要約すると次に効かない。

### 周の終わりに、自分の側の振り返りも書く

先生の指摘とは別に、この周で**自分が何を外したか**を1〜3行で書き足す。

```markdown
### この周の自己振り返り（AI側）
- 外したこと: <何を見落としたか>
- 次からの手当て: <ルーティンのどこをどう変えるか>
```

ルーティン自体を変える必要があるなら、`SKILL.md` か `references/` を直す。
蓄積しないと、同じ外し方を繰り返す。

## Round 7 — 別の単元で効くかを確かめる（2〜3周ごと）

`_review-notes.md` が育ってきたら、**その効果を空から確かめる。**

別の単元を1つ選び、`_review-notes.md` だけを根拠に（生徒役も critic も通さずに）
ワークシートを1枚作ってみる。

- 基準が効いていれば、1周目から穴うめが少なく、深い問いが2問入ったものが出る。
- 効いていなければ、基準の書き方が抽象的すぎる。判定できる文に書き直す。

これは成果物を作るためではなく、**蓄積した基準が機能しているかのテスト**。
作ったものは先生に出さなくてよい。

## 行き詰まったとき

- 生徒役の答案が全員正解で綺麗すぎる → 生徒役が優等生化している。
  知識の天井とペルソナを再提示してもう一度走らせる。
- critic が全問を褒める → 「いちばん弱い問題を1つ名指しせよ」と再指示する。
- エージェント名で呼べない（`Agent type not found`）→ エージェント定義はセッション開始時に
  読み込まれる。作った直後のセッションでは名前で呼べない。その場合は `general-purpose` で起動し、
  プロンプトの冒頭で `.claude/agents/<名前>.md` を読んで役割を引き受けるよう指示する。
  次のセッションからは名前で呼べる。
- 差し替え案が思いつかない → `references/deepening-moves.md` の手筋を上から順に当てる。
