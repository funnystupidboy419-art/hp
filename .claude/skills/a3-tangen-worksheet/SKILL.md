# 単元A3ワークシート生成

『学び合い』の授業で使う、1時間＝A3横1枚のワークシートを単元分まとめて作る。
生徒用と教師用赤刷りを**同じデータから2回ビルド**するのが中心。Word/PDFは手で直さず、必ずソース側を直す。

## 最初に確認すること

作業に入る前に、次が決まっていなければ聞く。

- 単元名・教科書のページ範囲・**時数**（＝作る枚数）
- 単元を貫く課題（教科書の節扉や導入から取ると外れにくい）
- 「最低限おぼえること」＝**根拠カード**を何枚に絞るか（10枚前後。証明・説明で「〜だから」と書ける命題だけ）
- 小テスト・単元テストの有無。**単元テストが市販プリントなら、その大問構成を先に読む**（後述）

## 1枚のレイアウト（固定）

A3横、5ブロックを左→右。授業の50分の流れとそのまま対応させる。

| | 列幅(twips) | 時間 | 中身 |
|---|---|---|---|
| ① 前時の復習 | 3600 | 5分 | 根拠カードの確認。ペアで「昨日の1つ」を説明 |
| ② 今日やること | 4400 | 5分 | めあて、語り、使う根拠カードの番号を書く欄 |
| ③ 練習 | 5600 | 20分 | 教科書の問＋プリント。答えだけでなく「根拠カードの何番？」 |
| ④ JUMP課題 | 5477 | 12分 | 別解・説明・発展。1人では届かない設定 |
| ⑤ ふりかえり | 3600 | 8分 | 使った根拠カード番号／だれを助けたか・助けられたか |

合計22677 twips がA3横の本文幅。ヘッダーに「第N時／教科書ページ／めあて／語り」を1行で入れる。

## 生徒用と赤刷りの二重ビルド

データは1か所。`setTeacher(true)` で出し分ける。

- `pz("∠x＝【65】°")` … 生徒用は空白（答えの文字数×1.7の全角スペース）、教師用は赤太字
- `rz(n, ["模範解答1行目", ...])` … 生徒用は罫線n本、教師用は赤字の解答＋残りを罫線で埋める
- `figt(図a, 図b, mm)` … 生徒用は図a、教師用は**補助線入り**の図b

**赤刷りの図には必ず補助線を入れる。** 補助線なしの解答図は、生徒が見ても再現できない。

### 1ページぴったりに収める

各要素に mm 単位の推定高さ `_h` を持たせ、列の合計が `TARGET` になるまで罫線を自動で足す。

- TARGET：生徒用 224mm／教師用 214mm（赤字の解答が入るぶん教師用を低くする）
- 行の高さ：`HeightRule.ATLEAST` で 236mm／226mm
- 高さ推定では**テキストの折り返し行数を数える**こと。数えないと赤刷りだけ溢れる

溢れたときの直し方は、要素を消すのではなく ①図のmmを小さくする ②`rz()` の本数を減らす の順。

## 図はコードで描く

SVGを生成→PNGにしてWordに貼る。図をPowerPointや画像の切り貼りで作らない。

- **角度ラベルは実座標から計算した値を書く**。手で数字を置かない。頂点3点から角度を出す関数を用意し、`f"{round(v)}°"` で出す。図と答えがずれる事故はこれで防げる
- 円弧は放っておくと長い方に回る。**∠UVW は必ず「180°未満になる側」を選ぶ関数経由で描く**
- 赤刷り用の図は、元図をコピーして色を変えた線を足す方式
- ラスタライズ（cairosvg）では、`<text>` に `font-family="Noto Sans CJK JP, DejaVu Sans, sans-serif"` を**属性として直付け**する。生成SVGに `xmlns` がないと `<style>` ブロックは効かず、㋐㋑㋒㋓ が豆腐になる
- 拡大率は 3.4（Word上で 1mm ≒ 3.4px）

## 単元テストが市販プリントのとき

先に本番プリントの**大問構成・配点・観点の内訳**を読み取り、表にする。そのうえで

1. 「テストに出る◯つの形」を大問に1対1で対応させ、生徒用の見通しシートに載せる
2. 各形が**どの時間・どの小テスト・どの宿題で練習できるか**を必ず1つ以上埋める。空欄が残る形は、練習の穴
3. 本番に出ない領域（用語・逆と反例など）も、証明で使うなら指導は落とさない

自作していたテストは捨てず、再テスト・発展用の「予備テスト」に位置づけ直す。

## 検証（毎回やる）

```bash
soffice --headless --convert-to pdf out/xxx.docx --outdir out/
pdfinfo out/xxx.pdf | grep Pages          # 時数と一致するか
pdftoppm -jpeg -r 68 out/xxx.pdf /tmp/p   # 画像にして目視。白紙ページの混入を確認
```

生徒用・赤刷りとも**ページ数＝時数ちょうど**が正常。1ページでも多ければ溢れている。
PILで各ページの平均輝度を見ると、白紙ページを機械的に拾える。

**答えは全部自分で検算する。** 図と設問の食い違いは毎回出る。とくに

- 分類の図に答えが印刷されていないか（「鋭角三角形」等のキャプション）
- 引いた対角線・補助線で本当に合同／成立するか
- 記号の付け方と設問の条件が合っているか

## 文言・体裁

- 図は本文の下に中央寄せで入るので「右の図」と書かない。**「次の図」「下の図」**
- 手書き風フォントやカラフルな配色は使わない。読みやすさを優先する
- **生徒の個人情報は入力しない・出力しない。** 名前は教科書の登場人物のみ

## 単元の他の成果物

ワークシートだけで終わらせず、同じデータから次も作れる。

- 単元構想（教師用・Word）／単元の見通し（生徒用・A4両面）
- 小テスト・宿題プリント（A4片面15分、穴うめ→部分記述→全部記述の順に難度を上げる）
- 単元計画表（Excel）：**前の単元のファイルをひな型として読み込み、書式を変えず値だけ差し替える**
- 視覚教具アプリ（単一HTML、ドラッグで角が変わる。1人1台と大画面提示の切替つき）

最後に、設計思想・ビルド手順・落とし穴を書いた `CLAUDE.md` を同梱して、
ソース一式をzipで渡せるようにしておく。次の単元はそれを土台にできる。

## コード側の実装メモ

既存プロジェクト（4章の `zukei4` など）がある場合は、`build_ws.js`（レイアウトエンジン）と
`figs.py` の `Fig` クラスをそのまま流用し、単元ごとのデータ（`run_ws.js`）と図だけ差し替える。

### ページ設定（A3横）

`docx` の `PageOrientation.LANDSCAPE` は **縦向きの寸法と組み合わせる**。
`width: 420, height: 297` と書くと A3 縦で出力されるので注意。

```js
size: { width: mm(297), height: mm(420), orientation: PageOrientation.LANDSCAPE },
margin: { top: mm(10), bottom: mm(8), left: mm(10), right: mm(10) },
```

### 1時間分のデータ構造

`sheet(L)` は**1時間ぶんのオブジェクトを1つ**受け取り、Paragraph/Table の配列を返す（配列を渡すと落ちる）。

```js
{
  n: 1, pages: "p.147-149", title: "…", goal: "本時のめあて",
  katari: "第1時の語り", cardline: "使う根拠カード ⑫⑬", mikan: "",
  review: [...], today: [...], practice: [...], jump: [...]   // ⑤ふりかえりは自動生成
}
```

`rule(n)` などは配列を返すので、ブロックに入れるときは `...rule(4)` とスプレッドする。

### ビルドの順番

```bash
python3 figs.py && python3 figs2.py && …   # 後段が figs.json を読んで追記するので順番厳守
python3 render.py                          # figs.json → png/ ＋ dims.json/dims2.json
node run_ws.js                             # 生徒用・赤刷りの2種を out/ に出力
```

`figs2.py` 以降で `from figs import ...` すると figs.py が再実行されて figs.json が初期化される。
直後に前段のモジュールを `import` して復元してから `json.load` すること。
